# کسب‌یاب (KasbYab)

سامانه‌ی جست‌وجو و معرفی کسب‌وکارها — نسخه اولیه (MVP)

کسب‌یاب به کاربران اجازه می‌دهد بر اساس **شهر** و **نوع خدمت** کسب‌وکارها را پیدا کنند، طرح معرفی، اطلاعات تماس، مسیریابی و شبکه‌های اجتماعی هر کسب‌وکار را ببینند و از **QR اختصاصی** و **ویترین حرفه‌ای** (اشتراکی) استفاده کنند. صاحبان کسب‌وکار پنل مستقل دارند و بخش **طراحان کارت‌ویزیت** با کد معرفی و پورسانت از ابتدا در ساختار دیده شده است.

## 🚀 اجرای سریع (توسعه)

```bash
npm install
cp .env.example .env
# در .env برای توسعه مقدار DATABASE_URL را روی این آدرس بگذارید:
# DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5432/app_db
# همچنین ADMIN_EMAIL، ADMIN_PASSWORD و DEMO_OWNER_PASSWORD را تنظیم کنید.

# ۱) دیتابیس توسعه (PostgreSQL واقعی در WASM — بدون نیاز به نصب چیزی)
npm run db:server

# ۲) در ترمینال دوم: ساخت جداول و داده‌های نمونه
npm run db:setup

# ۳) اجرای سایت
npm run dev
```

باز کنید: <http://localhost:3000>

> برای تولید، به‌جای PGlite یک PostgreSQL واقعی ست کنید: `DATABASE_URL` را در فایل `.env` (کپی از `.env.example`) بگذارید و migration را اجرا کنید. در production نبودِ `DATABASE_URL` مانع بیلد نمی‌شود؛ صفحات عمومی با داده‌ی نمونه‌ی پشتیبان باز می‌شوند، اما عملیات نوشتن مثل ثبت‌نام، ورود، سفارش و گزارش تا زمان اتصال دیتابیس عمداً متوقف می‌مانند.

### استقرار در Vercel

1. یک دیتابیس PostgreSQL واقعی بسازید (Neon، Supabase یا Vercel Postgres).
2. در تنظیمات پروژه Vercel این متغیرها را ست کنید:
   - `DATABASE_URL` — آدرس PostgreSQL از بخش Connect در Supabase (اجباری)
   - `AUTH_SECRET` — یک رشته تصادفی طولانی برای امضای سشن‌ها (اجباری)
   - `ADMIN_EMAIL` و `ADMIN_PASSWORD` — مشخصات مدیر اولیه (رمز حداقل ۸ کاراکتر)
   - `NEXT_PUBLIC_SITE_URL` — آدرس نهایی سایت، مثلاً `https://kasbyab.ir`
   - `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — اختیاری و برای اتصال‌های عمومی آینده
3. جداول و داده‌های نمونه را روی همان دیتابیس اعمال کنید (فقط یک‌بار روی دیتابیس خالی):
   ```bash
   DATABASE_URL="postgresql://..." npm run db:migrate
   DATABASE_URL="postgresql://..." ADMIN_EMAIL="admin@example.com" ADMIN_PASSWORD="یک-رمز-قوی" DEMO_OWNER_PASSWORD="رمز-نمونه-قوی" npm run db:seed
   ```
   یا فایل `supabase/schema.sql` را در SQL Editor اجرا کنید و سپس فقط seed را اجرا کنید.
   **هشدار:** `db:seed` داده‌های قبلی را برای ساخت دیتای دمو پاک می‌کند؛ روی دیتابیس دارای داده واقعی اجرا نکنید.
4. Deploy کنید و بعد `/admin` را با `ADMIN_EMAIL` و `ADMIN_PASSWORD` باز کنید. اگر جدول `admins` خالی باشد، اولین ورود با همین متغیرها مدیرکل را خودکار می‌سازد.

### اتصال Supabase

این پروژه از PostgreSQL سمت‌سرور و Drizzle استفاده می‌کند؛ بنابراین برای اتصال Supabase، **Database URL** بخش Connect را در `DATABASE_URL` قرار دهید. کلیدهای `sb_publishable` برای مرورگر و `sb_secret` فقط در صورت استفاده از APIهای سروری لازم‌اند و نباید در Git یا کد کلاینت ذخیره شوند. فایل SQL آماده‌ی Supabase در `supabase/schema.sql` قرار دارد.

روند پیشنهادی:

```bash
cp .env.example .env
# DATABASE_URL، AUTH_SECRET، ADMIN_EMAIL، ADMIN_PASSWORD و DEMO_OWNER_PASSWORD را در .env تنظیم کنید
npm run db:migrate
npm run db:seed       # فقط روی دیتابیس خالی؛ دیتای قبلی را پاک می‌کند
npm run build
```

اگر هنگام اتصال مستقیم خطای شبکه گرفتید، از **Transaction pooler** در Supabase استفاده کنید و URI را دقیقاً از دکمه Connect کپی کنید.

### حساب‌های آزمایشی

| نقش | ورود | رمز |
|---|---|---|
| مدیر کل | مقدار `ADMIN_EMAIL` (از مسیر `/admin`) | مقدار `ADMIN_PASSWORD` |
| صاحب کسب‌وکار نمونه | `09120000000` (از مسیر `/owner`) | مقدار `DEMO_OWNER_PASSWORD` |

`npm run db:seed` فقط با رمزهای محیطی حداقل ۸ کاراکتری اجرا می‌شود و آن‌ها را در source یا Git ذخیره نمی‌کند.

## ✨ امکانات نسخه اول

### بخش عمومی
- صفحه اصلی با جست‌وجوی **نوع خدمت + شهر** و دسته‌بندی‌ها
- صفحه نتایج با **مینی‌کارت**، باکس جست‌وجوی فعال، فیلترهای شهر/دسته و فیلترهای وضعیت (دارای جواز، عضو اتحادیه، دارای ضمانت، ویترین حرفه‌ای، تأیید پلتفرم)
- **نقشه تعاملی ایران** با شهرهای نمونه و لینک مستقیم فیلتر شهر
- صفحه اختصاصی هر کسب‌وکار با **لینک مستقل**، اطلاعات تماس، آدرس، نقشه OpenStreetMap و مسیریابی (Google Maps) و شبکه‌های اجتماعی
- **QR اختصاصی** هر کسب‌وکار (تولید سمت سرور + دانلود PNG)
- نشان‌های وضعیت با **توضیح شفافِ خوداظهاری** (تفاوت «تأیید پلتفرم» با نشان‌های اظهاری)
- **سیستم گزارش مردمی** برای اطلاعات نادرست (از نوار پایین موبایل یا دکمه دسکتاپ)
- **ثبت سفارش عمومی** برای محصول/خدمت، کد پیگیری و مدیریت وضعیت از پنل صاحب کسب‌وکار و مدیر
- بلاگ و صفحه طراحان

### پنل صاحبان کسب‌وکار
- ثبت‌نام/ورود، **تأیید حساب توسط مدیریت**
- ثبت و ویرایش مشخصات کسب‌وکار، تماس، آدرس، موقعیت، شبکه‌های اجتماعی، نشان‌های اظهاری
- وضعیت تأیید کسب‌وکار (در انتظار / فعال / تعلیق) همراه یادداشت مدیریت
- مدیریت ویترین (عکس/محصول/قیمت) با **سقف ۴ آیتم در طرح رایگان** و سقف بالاتر با اشتراک
- **درخواست اشتراک** (انتخاب پلن + کد معرفی طراح)

### کارت‌ویزیت‌ساز
- چند قالب استاندارد (کلاسیک / مینیمال / فاخر) + انتخاب رنگ زمینه و اندازه متن
- اطلاعات به‌صورت **خودکار از پروفایل** پر می‌شود (نام، شعار، تماس، آدرس، اینستاگرام، لینک اختصاصی)
- QR به‌صورت خودکار روی کارت درج می‌شود
- **دانلود PNG با کیفیت چاپ** (بدون نیاز به نرم‌افزار طراحی)

### ویترین حرفه‌ای و اشتراک
- پلن‌ها (رایگان/پایه/حرفه‌ای/طلایی) با مدیریت کامل از پنل مدیریت
- تاریخ شروع/پایان، وضعیت فعال/منقضی/در انتظار برای هر اشتراک
- فعال‌سازی اشتراک توسط مدیریت → فعال‌شدن ویترین و ارتقای سقف آیتم‌ها

### طراحان کارت‌ویزیت
- پروفایل عمومی، نمونه‌کار (با تأیید مدیریت)، امتیاز و رتبه، کد معرفی اختصاصی
- ثبت **معرفی (رفرال)** هنگام درخواست اشتراک کسب‌وکار با کد طراح — داده از روز اول کامل ذخیره می‌شود تا محاسبه پورسانت در فاز بعد بدون بازطراحی اضافه شود

### پنل مدیریت مرکزی (`/admin`)
- نمای کلی با آمار زنده و کارهای در انتظار
- تأیید/رد/تعلیق کسب‌وکارها، نشان «تأیید پلتفرم» و «ویژه»
- مدیریت کاربران (تأیید حساب، تعلیق)
- مدیریت دسته‌بندی‌ها و شهرها
- رسیدگی به گزارش‌های مردمی با یادداشت مدیریت
- مشاهده و مدیریت سفارش‌های مشتریان (تأیید، تکمیل یا لغو)
- مدیریت پلن‌ها، اشتراک‌ها (فعال‌سازی/لغو)، طراحان و نمونه‌کارها، معرفی‌ها و پورسانت
- مدیریت بلاگ و مدیران سامانه (مدیرکل می‌تواند مدیر بسازد)
- **سوابق مدیریتی (Audit Log)** کامل با جست‌وجوی رویدادها

## 🔒 امنیت (زیرساخت، نه فاز بعدی)

- رمزهای عبور با **scrypt + نمک تصادفی** و مقایسه timing-safe
- سشن‌های امضاشده HMAC-SHA256 با انقضا (کوکی httpOnly / SameSite=Lax / Secure در production)
- **احراز دومرحله‌ای (TOTP)** برای ورود مدیریت — سازگار با Google Authenticator (زیرساخت آماده؛ فعال‌سازی با یک دستور در دیتابیس)
- محدودسازی نرخ درخواست (ثبت‌نام، ورود، گزارش، اشتراک، ثبت کسب‌وکار)
- اعتبارسنجی ورودی‌ها در لایه سرور (تلفن، ایمیل، URL امن، طول فیلدها، مختصات)
- فقط آدرس‌های `http/https` برای تصاویر پذیرفته می‌شود؛ HTML ورودی پاک‌سازی می‌شود
- سطح‌بندی دسترسی: مدیرکل / مدیر / اپراتور / صاحب کسب‌وکار / کاربر عمومی
- کسب‌وکارهای جدید تا تأیید مدیریت **عمومی نمایش داده نمی‌شوند**
- هدرهای امنیتی (X-Frame-Options، nosniff، Referrer-Policy، Permissions-Policy)
- ثبت رخدادهای مهم مدیریتی (Audit Log)
- **توصیه‌های استقرار:** SSL (اجباری — کوکی‌ها در production فقط Secure هستند)، `AUTH_SECRET` تصادفی، بکاپ خودکار روزانه دیتابیس، پشت Cloudflare یا معادل برای WAF/محدودسازی نرخ

## 🧱 ساختار فنی

- **Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS 4**
- **Drizzle ORM + PostgreSQL** (توسعه: PGlite با پروتکل وایر — بدون نصب دیتابیس)
- اسکریپت‌ها:
  - `npm run db:server` — سرور دیتابیس توسعه (PGlite)
  - `npm run db:migrate` — مهاجرت ایمن (idempotent)
  - `npm run db:seed` — داده‌های نمونه
  - `npm run db:setup` — هر دو با هم
  - `npm run typecheck` / `npm run lint` / `npm run build`
