# معیارهای پذیرش قابل آزمون — پرداخت مرحله‌ای

اصول: هر مرحله فقط با «اجرای موفق معیار» پذیرفته می‌شود؛ معیارها بر مبنای تست خودکار یا دستور قابل تکرار هستند.

## مرحله ۰ — بک‌اند MVP (این PR)
| # | معیار | دستور/روش آزمون | نتیجه مورد انتظار |
|---|---|---|---|
| 1 | بیلد و بالا آمدن استک | `docker compose up -d` | هر ۴ سرویس سالم |
| 2 | مایگریشن PostGIS | `docker compose exec backend php artisan migrate --force` | `postgis` فعال، جداول ساخته شود |
| 3 | تست‌های خودکار | `docker compose exec backend php artisan test` | همه Feature tests سبز |
| 4 | OTP | `curl -X POST .../api/v1/auth/otp/request -d '{"phone":"09121111111"}'` | 200 + کد در لاگ پیامک |
| 5 | جست‌وجوی شعاعی | `curl ".../businesses/search?lat=35.6997&lng=51.338&radius=2000"` | ترتیب فاصله صعودی |
| 6 | چرخه اشتراک | سناریوی `SubscriptionFlowTest` | فعال‌سازی خودکار + یادآوری ۷ روزه |
| 7 | QR | `curl -I .../api/v1/cards/{slug}/qr.png` | `Content-Type: image/png` |
| 8 | نقش‌ها | درخواست مالک به `/admin/*` | HTTP 403 |
| 9 | CI | push روی مخزن | هر دو job (backend/frontend) سبز |

## مرحله ۱ — اتصال کامل رابط (F1)
| # | معیار | روش آزمون |
|---|---|---|
| 1 | تمام صفحات عمومی از API لاراول بخوانند | غیرفعال کردن لایه Drizzle؛ سایت همچنان کار کند |
| 2 | ورود با OTP در UI | پیامک واقعی دریافت و ورود موفق |
| 3 | پنل مالک روی API | ثبت کسب‌وکار + درخواست اشتراک + آپلود رسید در UI |
| 4 | پنل مدیریت روی API | تأیید رسید → فعال شدن اشتراک در UI |
| 5 | پنل طراح روی API | لینک معرف + مشاهده پورسانت |
