# محدوده MVP کسب‌یاب — پیشنهاد مکتوب (نسخه برای تأیید کارفرما)

> این سند به نامه «ثبت دقیق محدوده MVP و معماری فنی» پاسخ می‌دهد و هر هشت بند درخواستی را به‌صورت مکتوب و قابل آزمون تعریف می‌کند. معماری مطابق مصوبه: **Next.js + TypeScript (رابط کاربری) / Laravel + PHP 8.3 (بک‌اند) / PostgreSQL + PostGIS / Redis**.

---

## ۱) جست‌وجوی شعاعی با PostGIS، مرتب‌سازی نزدیک‌ترین و ذخیره موقعیت کاربر

**تحویل:**
- ستون `businesses.location` از نوع `geography(Point,4326)` + ایندکس فضایی GIST.
- اندپوینت `GET /api/v1/businesses/search?lat=&lng=&radius=&category_id=&q=`
  - فیلتر با `ST_DWithin` (متر)، مرتب‌سازی پیش‌فرض با `ST_Distance` (نزدیک‌ترین به دورترین)، سقف شعاع ۵۰km (قابل تنظیم).
- ذخیره موقعیت انتخابی کاربر: `PUT /api/v1/auth/location` → ستون‌های `users.lat/lng/location_updated_at`. تا **تغییر دستی بعدی**، جست‌وجو از این موقعیت استفاده می‌کند (`center.source=saved`).

**معیار پذیرش قابل آزمون:** با سه کسب‌وکار در فواصل ۱/۴/۱۰ کیلومتری، خروجی دقیقاً به ترتیب «نزدیک، متوسط، دور» باشد؛ با `radius=2000` فقط «نزدیک» برگردد؛ پس از `PUT /auth/location` جست‌وجو بدون پارامتر از همان نقطه استفاده کند. (تست: `tests/Feature/RadiusSearchTest.php`)

## ۲) ورود با شماره موبایل و اتصال پیامک واقعی

**تحویل:**
- `POST /api/v1/auth/otp/request` و `POST /api/v1/auth/otp/verify` (Sanctum Token).
- کد ۶ رقمی، هش‌شده، TTL ۵ دقیقه، حداکثر ۵ تلاش، محدودیت بازارسال (۶۰ ثانیه)، لاگ کامل در `security_logs` و `sms_logs`.
- اتصال پیامک واقعی از طریق درایورهای **Kavenegar / Ghasedak / SMS.ir** (`config/kasbyab.php` + `SMS_DRIVER`). درایور `log` فقط برای توسعه است.
- نرمال‌سازی شماره‌های `+98/0098/98/0` به قالب `09xxxxxxxxx`.

**معیار پذیرش:** با `SMS_DRIVER=log` تست‌های `OtpAuthenticationTest` سبز شود؛ با کلید واقعی کاوه‌نگار، پیامک واقعی دریافت شود (آزمون دستی با شماره واقعی + ثبت در `sms_logs`).

## ۳) پنل مالک، پنل طراح و پنل مدیریت با نقش‌ها و دسترسی‌های مشخص

**تحویل:**
- نقش‌ها: `admin | owner | designer | user` (ستون `users.role` + Gate/Middleware `role:`).
- API پنل مالک: مدیریت کسب‌وکارها، درخواست اشتراک/رسید، کارت‌ها.
- API پنل طراح: کد معرف، لینک، پورسانت‌ها (`/api/v1/designer/*`).
- API پنل مدیریت: آمار، بررسی درخواست‌ها، تعدیل کسب‌وکارها، نقش کاربران، لاگ‌ها (`/api/v1/admin/*`).
- ماتریس دسترسی: مدیر = همه‌چیز؛ مالک = کسب‌وکار/اشتراک/کارت خودش؛ طراح = پروفایل و پورسانت خودش.

**معیار پذیرش:** `RoleAndReferralTest` — مالک به `/admin/*` با ۴۰۳ برخورد کند، مهمان ۴۰۱، مدیر ۲۰۰.

## ۴) درخواست اشتراک، رسید پرداخت آفلاین، تأیید مدیر، شروع/پایان خودکار و یادآوری تمدید

**تحویل:**
- `plans` (نام/قیمت/مدت/امکانات) + `POST /owner/subscription-requests`.
- بارگذاری رسید (jpg/png/pdf تا ۵MB) روی دیسک خصوصی + شماره پیگیری؛ رویداد در `security_logs`.
- تأیید/رد مدیر با یادداشت → ساخت خودکار `subscriptions` با `starts_at/ends_at` (از مدت پلن).
- زمان‌بندی روزانه: `subscriptions:expire` (پایان خودکار) و `subscriptions:remind` (یادآوری ۷/۳/۱ روز مانده، یک‌بار برای هر نقطهٔ زمانی — ثبت در `reminders_sent`).

**معیار پذیرش:** `SubscriptionFlowTest` — چرخه کامل سبز شود؛ دستور `expire` اشتراک گذشته را «expired» کند؛ یادآوری ۷ روزه فقط یک‌بار ارسال شود.

## ۵) حداقل سه قالب پویای کارت، QR اختصاصی، بارگذاری طرح چاپی، کد/لینک معرف طراح

**تحویل:**
- ۴ قالب کارت seed می‌شود (`classic/modern/minimal/bold`) با پیکربندی JSON.
- `POST /owner/cards` → slug یکتا + `GET /api/v1/cards/{slug}/qr.png` (PNG واقعی سمت سرور) + لینک کوتاه `/c/{slug}`.
- بارگذاری طرح چاپی موجود: `POST /owner/cards/{id}/print` (تا ۱۰MB).
- کد معرف: `designer_profiles.code` + لینک `/r/{code}` (لندینگ `GET /api/v1/referrals/{code}`)، اتصال کاربر معرفی‌شده و پورسانت خودکار هنگام تأیید اشتراک (`referral_rewards`).

**معیار پذیرش:** `DuplicateAndCardsTest` و `RoleAndReferralTest` — QR با Content-Type صحیح، پورسانت ۱۵٪ روی پلن ۱٬۰۰۰٬۰۰۰ تومانی = ۱۵۰٬۰۰۰.

---

## ۶) تشخیص کسب‌وکار تکراری، حذف نرم، سوابق مدیریتی و لاگ امنیتی

**تحویل:**
- تشخیص تکرار: شماره تماس نرمال‌شدهٔ یکسان در شهر + نام نرمال‌شده یکسان/مشابه (شباهت ≥ ۸۵٪) → پاسخ `409` با فهرست موارد مشابه؛ ثبت در لاگ؛ امکان ثبت با `force` (فقط با ثبت در لاگ امنیتی).
- حذف نرم (`SoftDeletes`) برای کسب‌وکارها + بازیابی توسط مدیر + حذف قطعی فقط مدیر.
- `audit_logs`: هر ایجاد/ویرایش/حذف/تأیید/تغییر نقش با `before/after`، کاربر، IP.
- `security_logs`: otp_requested/verified/failed/rate_limited، receipt_uploaded، subscription_approved، duplicate_attempt، role_changed.

**معیار پذیرش:** `DuplicateAndCardsTest` — شماره تکراری ۴۰۹؛ حذف نرم از نمای عمومی مخفی ولی در دیتابیس موجود؛ ردیف `audit_logs` با action=deleted.

## ۷) مخزن خصوصی گیت از روز اول تحت مالکیت کارفرما

**تحویل:**
- کد از همین روز در مخزن گیت (این PR) با تاریخچه تمیز و کامیت‌های موضوعی.
- `.github/workflows/ci.yml`: تست‌های PHP روی PostgreSQL+PostGIS واقعی و بیلد فرانت‌اند روی هر push.
- توصیه‌نامه انتقال مالکیت (transfer مخزن به اکانت کارفرما + Admin merge protection) در `docs/ownership.md`.

**معیار پذیرش:** تاریخچه گیت از اولین کامیت قابل مشاهده و CI سبز روی commit های مخزن.

## ۸) استقرار، پشتیبان‌گیری، بازگشت نسخه، مستندات و ۳ ماه پشتیبانی

**تحویل:**
- `docker-compose.yml` آماده (PostgreSQL+PostGIS، Redis، بک‌اند، فرانت) + `docs/deployment.md` (nginx/php-fpm، متغیرها، SSL).
- پشتیبان: اسکریپت `pg_dump` زمان‌بندی‌شده + رویه بازگردانی؛ بازگشت نسخه با تگ‌های گیت + مایگریشن‌های رو به جلو (migrate/rollback).
- مستندات: README، این سند، `docs/acceptance-criteria.md`، `docs/testability-matrix.md`.
- **تعهد ۳ ماه رفع خطاهای عملکردی و امنیتی** از تاریخ تحویل نهایی MVP (پاسخ‌گویی حداکثر ۱ روز کاری برای خطاهای بحرانی).

**معیار پذیرش:** `docker compose up` روی یک سیستم تمیز، تمام سرویس‌ها را بالا آورد و `/api/v1/bootstrap` پاسخ ۲۰۰ بدهد.
